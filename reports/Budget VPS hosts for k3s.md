# Buy RAM, not cores, for k3s agent pods

As of October 2026, **Contabo's Cloud VPS 12 (12 shared vCPU, 48 GB, about €20–25/mo plus a small US surcharge) is the best raw value** for a single-node k3s cluster of 3–8 Manor project pods. **OVHcloud US VPS-4 (8 vCPU, 24 GB, 200 GB NVMe, about $23–28/mo) is the best balanced pick**, because it pairs near-Contabo pricing with US-run sites in Virginia and Oregon, better measured consistency, and included daily backups. The measured workload explains why: agents average only **0.05–0.5 cores each but spike to 1.4–3.5 GB of RAM during lint and test runs**, so memory sets the node size and CPU only has to absorb short bursts. That turns the right pod spec into a **0.25–0.5 CPU request with no CPU limit, a 1 GiB memory request and a 4 GiB limit**, and the right node into **8 vCPU with 24 GB as the practical floor for 8 pods (32–48 GB comfortable)**. On those numbers a project costs roughly **$3–4/mo on Contabo or OVH at 8 pods, and $8–10/mo at 3 pods**. Mainstream clouds (Vultr, Linode, DigitalOcean) cost 5–10× more for the same RAM, Hetzner is effectively unbuyable and repriced in the US, and IONOS and Hostinger hide large renewal jumps. One finding matters more than any provider choice: ADR-234's Medium preset (2 CPU / 4 GiB requests) would force a 16 vCPU / 32 GiB node for 8 pods and roughly double the bill.

## Memory sets the node size; CPU only needs headroom for bursts

A 180-second sample of the user's dev box gives the baseline. The box ran 9 Claude Code agents, 5 of them actively implementing an ADR, linting and testing. **Idle agents used 0.01–0.08 cores and 220–500 MB. Agents editing or thinking averaged about 0.26 cores and 560 MB but peaked near 1.4 GB. An agent running `pnpm lint` plus tests averaged 0.45 cores but reached 9.7 cores and 3.5 GB at peak** ([measured_usage.md](../research_notes/Budget%20VPS%20hosts%20for%20k3s/measured_usage.md)). A single eslint pass over the Manor repo used about 870 MB on its own, and the Manor host server inside each pod adds about 80 MB at near-zero CPU. Across the whole 16-core machine, CPU averaged 3.3 cores but hit a p95 of 13.7 during concurrent lint and typecheck bursts ([measured_usage.md](../research_notes/Budget%20VPS%20hosts%20for%20k3s/measured_usage.md)).

The shape is clear. CPU demand is mostly idle with tens-of-seconds spikes, so a pod should request little CPU and carry no CPU limit, letting it borrow every idle core on the node during a build. Memory spikes are hard ceilings: **a 2 GiB limit would OOM-kill a lint run on a Manor-sized repo**, while 4 GiB covers the observed 3.5 GB peak. The sample is one three-minute window on a desktop that also ran other software, and repo size drives the peaks, so a much larger monorepo would push the limit higher. The estimate below also assumes roughly one busy agent per pod at a time.

| Item | Recommended value | Why |
|---|---|---|
| Pod CPU request | 0.25–0.5 | Steady state is 0.05–0.5 cores per agent |
| Pod CPU limit | none | Builds want 2–10 cores for tens of seconds |
| Pod memory request | 1 GiB | Active agents average 0.6–0.75 GB |
| Pod memory limit | 4 GiB | Lint/test peaks reach 3.5 GB |
| Node for 3 pods | 4–8 vCPU, 12–16 GB | One build (3.5 GB) plus two active pods plus k3s/OS |
| Node for 8 pods | 8 vCPU, 24 GB floor; 32–48 GB comfortable | Three concurrent builds (~10.5 GB) plus five active pods (~3.75 GB) plus host servers, k3s and OS |

The 8-pod arithmetic lands at about 16–17 GB in a realistic worst case, which is why the measured notes call 16 GB the minimum and 24–32 GB comfortable ([measured_usage.md](../research_notes/Budget%20VPS%20hosts%20for%20k3s/measured_usage.md)). In practice 16 GB leaves no margin for a fourth simultaneous build or a heavier repo, so 24 GB is the sensible floor to buy.

Requests, not usage, decide whether pods schedule. Under ADR-234's Medium preset, 8 pods request 16 CPU and 32 GiB, so the scheduler refuses them on an 8 vCPU or 24 GB node even though actual use would fit with room to spare. The notes estimate that preset **overstates CPU by about 4–8×** for these agents ([measured_usage.md](../research_notes/Budget%20VPS%20hosts%20for%20k3s/measured_usage.md)). Moving to the measured spec is what makes the €11–25 plans viable. Disk is the remaining sizing input: 8 PVCs of 20 Gi is 160 GB nominal plus images, so 200–400 GB of local disk is the target. The k3s local-path provisioner backs PVCs with host directories and does not enforce the 20 Gi size, so actual clone and `node_modules` usage, not the nominal claim, fills the disk.

## Contabo wins on RAM per dollar but sells far fewer real cores than it lists

Contabo relaunched its line in 2026 as Cloud VPS 4–18 (shared vCPU), Cloud VPS Plus 4–18 (shared AMD EPYC, more NVMe) and Cloud VDS S–XXL (dedicated EPYC 7282). Everything is month-to-month with no setup fee, and 12- or 24-month terms cut 15% or 20% ([Contabo VPS](https://contabo.com/en-us/vps/); [Contabo VDS](https://contabo.com/en-us/vds/)). The relevant plans are **Cloud VPS 8 (8 vCPU, 24 GB, 300 GB SSD or 150 GB NVMe) at €11.20 on 24 months or €14.00 monthly, and Cloud VPS 12 (12 vCPU, 48 GB, 400 GB SSD or 200 GB NVMe) at €20.00 or €25.00** ([Contabo VPS](https://contabo.com/en-us/vps/)). US sites (St. Louis, New York, Seattle) add roughly €1.3–1.9/mo according to a September 2026 third-party review, which Contabo's own page did not confirm ([affinco](https://affinco.com/contabo-pricing/)). At about €0.52/GB of RAM, nothing else in this comparison comes close.

The catch is CPU. A September 2026 YABS of an 18-vCPU Cloud VPS 18 scored **Geekbench 6 multi-core 2,971, roughly the throughput of a few dedicated modern cores**, and vpsbenchmarks graded its performance stability **F (0.82/20)** ([vpsbenchmarks YABS](https://www.vpsbenchmarks.com/yabs/contabo-18c-94gb-20260908-tg10813); [vpsbenchmarks trial](https://www.vpsbenchmarks.com/trials/contabo_performance_trial_08Sep2026)). Steal varies by host node. A December 2025 24-hour endurance run on Cloud VPS 10 saw 0% steal every hour ([vpsbenchmarks endurance](https://www.vpsbenchmarks.com/trials/contabo_performance_trial_12Dec2025/endurance_runs/last)), while LowEndTalk users report 60–80% steal on bad nodes ([LET](https://lowendtalk.com/discussion/206685/is-contabo-good)). For this workload, a parallel lint/test burst on Contabo will run noticeably slower than the vCPU count suggests, but the agents spend most of their time waiting on the Claude API, so slower builds are an annoyance, not a failure. The Plus line scored better (Raw CPU B, Stability C on Plus 4) and costs about 2.5× more, at **€28.00/mo for Plus 8 on 24 months** ([vpsbenchmarks compare](https://www.vpsbenchmarks.com/compare/contabo); [Contabo pricing](https://contabo.com/en-us/pricing/)). Dedicated VDS M (8 cores, 32 GB) costs €49.60–62.00 on older Zen 2 cores ([Contabo VDS](https://contabo.com/en-us/vds/)).

Operational trade-offs follow the price. Support is ticket-only with typical replies in 2–12 hours and 24–72 hours for complex or weekend issues; some users report abuse suspensions on recycled IPs; and there is a 14-day refund window ([learnwithhasan](https://learnwithhasan.com/vps-providers/contabo-vps/)). Contabo's status page logged a US Central (St. Louis) network incident on 2026-10-09 ([contabo-status.com](https://contabo-status.com/)). The terms bar programs that "extensively wear and/or tear" hardware and let Contabo set undisclosed limit values, but nothing bans Kubernetes or AI agents ([Contabo T&C](https://contabo.com/en/legal/terms-and-conditions/)). Bursty agent compiles sit well inside that line. For k3s the platform is fine: full KVM guests on stock Ubuntu kernels, cloud-init, snapshots, a firewall API and an official Terraform provider, but no nested virtualization and no attachable block volumes ([vpsbenchmarks YABS](https://www.vpsbenchmarks.com/yabs/contabo-18c-94gb-20260908-tg10813); [Contabo API](https://api.contabo.com/); [GitHub](https://github.com/contabo/terraform-provider-contabo)). The missing nested virtualization rules out Kata or Firecracker sandboxing for agent pods, though plain runc or gVisor still work.

## OVHcloud and Netcup give up a little RAM per dollar for steadier US-hosted nodes

**OVHcloud US VPS-4 (8 vCore, 24 GB, 200 GB NVMe, 3 Gbps, unlimited traffic) starts at $23.37/mo on a 12-month commitment**, with pay-monthly pricing around $27.50 ([OVHcloud US VPS](https://us.ovhcloud.com/vps/); [VPSBenchmarks OVHcloud US](https://www.vpsbenchmarks.com/compare/ovhcloud_us)). Daily backups are included ([OVHcloud US VPS](https://us.ovhcloud.com/vps/)). Its September 2026 trial graded Raw CPU C, Stability D, Disk B and Network B, and OVHcloud US's provider consistency score of 73 beats Contabo's 56 ([VPSBenchmarks OVHcloud US](https://www.vpsbenchmarks.com/compare/ovhcloud_us); [vpsbenchmarks compare](https://www.vpsbenchmarks.com/compare/contabo)). OVHcloud US is a separate company running sites in Vint Hill, VA and Hillsboro, OR ([OVHcloud VPS](https://www.ovhcloud.com/en/vps/)). The limit is size: the 2027 line tops out at VPS-4, so 24 GB is the ceiling. That covers 3–6 pods comfortably and 8 pods at the floor. Beyond that OVH means stepping up to dedicated hardware such as Rise, which was out of stock on October 15 ([OVH bare-metal prices](https://www.ovhcloud.com/en/bare-metal/prices/)).

**Netcup VPS 4000 (12 shared vCores, 32 GB, 512 GB) costs €45.36/mo net on a 12-month term, and VPS 2000 (8 vCores, 16 GB, 256 GB) costs €26.92**, with a US site in Manassas, VA ([netcup VPS page](https://www.netcup.com/en/server/vps)). A VPS 1000 in Vienna showed **0% steal** in both July and October 2026 tests ([serverkueche](https://serverkueche.de/en/tutorials/netcup-vps-1000-benchmark/)), and netcup's dedicated-core Root Server line (RS 2000: 8 EPYC 9645 cores, 16 GB, €40.70; RS 4000: 12 cores, 32 GB, €77.83) is the cheapest dedicated-core option with a US site ([netcup RS page](https://www.netcup.com/en/server/root-server)). Three cautions apply. Netcup's page does not say which plans Manassas stocks. A July 2026 review says sustained 100% CPU on shared vCores attracts throttling ([Valebyte](https://valebyte.com/en/blog/netcup-review-2026-the-price-performance-king-and-its-fine-print/)). And new accounts face Stripe ID-plus-selfie verification, with documented rejections ([netcup helpcenter](https://www.netcup.com/en/helpcenter/documentation/general/identity-verification); [netcup forum](https://forum.netcup.de/thread/19265-we-have-to-reject-your-order/)). Netcup's G12.5 refresh in September 2026 also halved built-in storage on some plans and dropped the NVMe guarantee ([serverkueche](https://serverkueche.de/en/tutorials/netcup-vps-1000-benchmark/)).

Hetzner, long the default answer, is no longer one. The June 15, 2026 repricing put **US CPX41 (8 vCPU, 16 GB) at €120.49 and CPX51 (16 vCPU, 32 GB) at €237.99**, with no cheap CX/CAX plans in the US and no US dedicated servers ([Hetzner docs](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/)). Since June 26 Hetzner's status page has also restricted new customers from creating cloud servers ([Hetzner status](https://status.hetzner.com/incident/0a75c7ae-3377-41dc-aabe-601063724d24)).

## US budget hosts trade promo cliffs, stock and old hardware against price

**Hostinger KVM 8 (8 vCPU, 32 GB, 400 GB NVMe, 32 TB) costs $25.99/mo prepaid, then renews at $49.99** ([Hostinger VPS](https://www.hostinger.com/vps-hosting); [Findstack](https://findstack.com/resources/hostinger-black-friday-2026)). On specs it is excellent: 32 GB fits 8 pods comfortably, and a July 2025 endurance run on KVM 8 showed 0% steal ([vpsbenchmarks Jul 2025](https://www.vpsbenchmarks.com/trials/hostinger_performance_trial_16Jul2025/endurance_runs)). The renewal nearly doubles the price, the plan page does not name US cities, and the fair-use policy URL returned 404. Over a four-year horizon it averages about $38/mo, still competitive.

**InterServer sells $3 slices (2 GB RAM, 40 GB SSD, 2 TB transfer each, about one core per two slices), so 16 slices give 8 cores, 32 GB and 640 GB for $48/mo**, month-to-month in New York, Dallas or Los Angeles with no renewal increase ([InterServer VPS](https://www.interserver.net/vps/); [WHTOP](https://www.whtop.com/plans/interserver.net/134639)). It is the most transparent pricing here, but there is no refund or trial, no built-in snapshots, and competitor sources claim older 2.1–2.4 GHz CPUs; those claims are biased and unverified ([Valebyte](https://www.valebyte.com/en/blog/interserver-vs-valebyte-the-difference-in-2026/)).

The rest fall out quickly. **IONOS XL+ (8 vCore, 16 GB) is $14 for three months, then $47** ([IONOS VPS](https://www.ionos.com/servers/vps)). BuyVM sells honest dedicated cores, but its largest High Volume plan is 7 cores and 28 GB at $105, and the page showed out of stock ([BuyVM](https://buyvm.net/kvm-dedicated-server-slices/)). RackNerd's standard plans top out at 7 vCPU and 12 GB for $55.99, its promos stop at 8 GB, and its ToS tells users who want to max out CPU to buy dedicated ([RackNerd KVM](https://www.racknerd.com/kvm-vps); [RackNerd ToS](https://www.racknerd.com/terms-of-service)). GreenCloud charges $80/mo for 8 cores and 16 GB at list price ([GreenCloud](https://greencloudvps.com/budget-kvm-vps.php)).

When builds become frequent enough that shared vCPU hurts, budget US dedicated servers become the next step. ReliableSite advertised an **EPYC 4545P (16 cores), 64 GB and 1 TB NVMe for $99/mo**, and a Ryzen 5600X with 64 GB for $79 ([LowEndSpirit ReliableSite](https://lowendspirit.com/discussion/9818/dedicated-servers-from-49-mo-amd-epyc-4545p-amd-ryzen-core-i9-10900k-xeon-and-more)). That is 2–4× Contabo's cost, but it turns the k3s scheduler's CPU numbers into real cores.

## Mainstream clouds charge 5–10× for consistency this workload barely needs

At the 8 vCPU / 32 GB size, **Vultr Regular costs $160/mo, Linode Shared $192, Lightsail $164, and dedicated tiers $240–252 (Vultr Optimized, DigitalOcean General Purpose)** ([Vultr plans API](https://api.vultr.com/v2/plans); [Linode types API](https://api.linode.com/v4/linode/types); [AWS Lightsail pricing](https://aws.amazon.com/lightsail/pricing/); [DO Droplet pricing](https://www.digitalocean.com/pricing/droplets)). DigitalOcean's largest Basic plan, 8 vCPU and 16 GB at $96, is RAM-short for 8 pods. The premium buys stability, network and API maturity rather than CPU: Vultr's $40 Regular 4-core plan graded only E on raw CPU in April 2026, while its newer VX1 line graded A on stability ([vpsbenchmarks Contabo vs Vultr](https://www.vpsbenchmarks.com/compare/contabo_vs_vultr)). The structural advantage is billing: DigitalOcean now bills per second ([DO Droplet pricing](https://www.digitalocean.com/pricing/droplets)), and free managed control planes at Vultr, Linode and DigitalOcean make scaling worker nodes to zero overnight possible ([Vultr docs](https://docs.vultr.com/support/products/vke/how-much-does-the-vultr-kubernetes-engine-cost); [Linode LKE API](https://api.linode.com/v4/lke/types); [DO Kubernetes pricing](https://www.digitalocean.com/pricing/kubernetes)). That only pays off if pods are idle most hours, and agents that sit at 0.05 cores still hold their RAM.

Oracle is the outlier. **PAYG Ampere A1 at 8 OCPU and 48 GB costs about $111/mo before credits and about $83 after the current 2 OCPU / 12 GB free allowance**, with 10 TB of free egress ([OCI price list API](https://apexapps.oracle.com/pls/apex/cetools/api/v1/products/?currencyCode=USD)). Oracle quietly halved the Always Free A1 allowance on 2026-06-15 without an announcement ([InfoQ](https://www.infoq.com/news/2026/07/oracle-cloud-free-tier-limits/)), "out of host capacity" errors remain documented ([OCI Always Free docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)), and A1 is arm64. For a system whose pods clone arbitrary repos and build them, any x86-only binary or image breaks a project, which makes Oracle a poor default.

The ranked recommendation follows from the table and the risks above. **First, best value: Contabo Cloud VPS 12** in St. Louis or New York on the SSD disk option. Buy it month-to-month first, run YABS and watch `%st` under a parallel build during the 14-day refund window, then move to a 12- or 24-month term once you have a good node. Drop to Cloud VPS 8 if you will stay at 5 pods or fewer. **Second, best balanced: OVHcloud US VPS-4**, for steadier disk and network, US-run sites and included backups at about the same price, provided 24 GB is enough. **Third, Netcup VPS 4000 in Manassas** when 8 pods need real headroom and you can pass KYC and confirm stock. **Fourth, Hostinger KVM 8** if prepaying 24 months is acceptable and the renewal is budgeted. **Fifth, InterServer** for the simplest no-commitment, no-cliff pricing. **Sixth, a budget dedicated server** (ReliableSite, Netcup RS) once builds stop being occasional. Oracle A1 qualifies only for arm64-clean repos, the mainstream clouds only if per-second billing and scale-to-zero matter, and Hetzner, IONOS, RackNerd, GreenCloud and BuyVM are out for this use case in October 2026.

## Conclusion

The question looked like a hunt for the cheapest vCPU, but the measurements turn it into a RAM-per-dollar question with a CPU-burst caveat. That favors oversold hosts more than it would for a CPU-bound service: the agents idle at a fraction of a core, so Contabo's weak per-vCPU throughput only shows up as slower lint runs, while its 48 GB for about $30 sets the price. The bigger lever is in Manor itself. Pod presets that request 2 CPU and 4 GiB push the node into a tier costing twice as much, so shipping the measured defaults (0.25–0.5 CPU request, no CPU limit, 1 GiB request, 4 GiB limit) saves more than switching providers would.

Several things remain unknown and should be checked before committing to a long term: Contabo's exact US surcharge and USD pricing, whether Netcup's Manassas site stocks VPS 4000, OVH US's no-commitment price, Hostinger's US cities, and how any of these hosts behave with three agents compiling at once rather than one synthetic benchmark. The 2026 RAM and SSD supply crunch, visible in Hetzner's restrictions, OVH's out-of-stock dedicated servers and Netcup's storage halving, also argues for locking a good node on a 12–24 month term once it passes a burn-in, because today's prices and stock are not guaranteed to last.
